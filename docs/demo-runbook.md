# Five-person demo runbook

## Ownership

| Owner | Deliverable |
| --- | --- |
| ML member 1 | Real device capture, five-person recordings, labels, stage model and complete-rep validation |
| AI member 2 | AI template/fallback checks, committed bot behavior, held-out model report and timing evidence |
| UX member | Five-stage/cosmetic visual QA, framing instructions, phone/tablet layouts and demo rehearsal |
| Developer 1 | Expo Go version alignment, mobile bridge/lifecycle, native fallback spike if required |
| Developer 2 | HTTPS Worker/D1 setup, room behavior, reward ledger, service and failure testing |

## Gates

| Window | Exit condition |
| --- | --- |
| 0–2h | Actual Android and Apple camera/landmarks/bridge run, first GLB loads; select capture route |
| 2–6h | P01–P04 data collected and validated; first classifier exported; initial real exercise loop works |
| 6–12h | Full solo match, calibration, saved guest progression and collection exercised |
| 12–18h | Two-device PvP, AI/fallback, cosmetics and untouched P05 evaluation complete |
| 18–22h | Failure cases, timing, resource lifecycle, calendar/reward behavior and device responsiveness checked |
| 22–24h | Freeze, real rehearsal, evidence capture and honest limitations slide |

The hour-two choice is evidence-based. The native Android scaffold has separate setup/build risks. If neither path captures real movement, record a camera integration blocker. Synthetic rep protocol tests do not satisfy the camera demo.

## Physical checklist

Record device model, OS, Expo Go version, app revision, capture route, model version, date and tester. Keep Android, iPhone and iPad results separate.

- Grant and deny camera permission; retry without an unexplained blank screen.
- Check portrait/landscape, front-camera mirroring and video orientation.
- Stand fully in frame, perform two practice squats, transition safely, then two practice push-ups.
- Test full reps, shallow reps, holds, unrelated movement, partial bottom cycles and leaving the frame. Require top-bottom-top after reacquisition.
- Check both exercises with ten clean manually counted reps per trial; retain mistakes. Target at most one count error per ten clean repetitions.
- Verify switching exercise/phase resets a partial cycle, late events do not enter the wrong phase, and recovery never earns reps.
- Run sustained sessions. Record observed inference completion rate, time from completed rep to HUD update, and heat/stalls; report actual measurements only.
- Background/foreground, stop, navigate away, disable network and close the other player's app. Both players must see interruption with no completion reward.
- Load all five stage previews and every cosmetic on each stage. Confirm locked items cannot be equipped and preview does not change XP/stage/ownership.
- Rotate the hero, test idle/flex/victory and reduced motion. Measure viewer frame rate, target 30 FPS, and inspect repeated-navigation memory growth.
- Complete a real solo and a two-device PvP match, restart both apps, and confirm profile/reward persistence. Use a fresh player to show first-session Developing evolution from a qualifying workout.

## Rehearsal order

1. State that verified repetitions power a shared, server-owned match and cosmetics reward consistency.
2. Show camera framing and real practice repetitions, including a rejected partial movement.
3. Complete a live solo or private match. Explain guard, attack and simultaneous settlement using the visible HUD.
4. Show the saved reward receipt and earned first evolution. Restart or refresh the profile to demonstrate persistence.
5. Preview Legendary and the locked aura while keeping the earned stage visibly unchanged.
6. Show the actual held-out report, small-dataset limits, device matrix and next milestone.

Keep a recording of a successful real-camera rehearsal for presentation contingency, labeled as recorded. Never present synthetic input, a protocol smoke test, a prerecorded capture, or a previewed locked stage as a live earned result.
